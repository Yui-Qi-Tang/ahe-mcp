# 系統狀態、決策依據與重試的評估方法

版本：`state-decision-retry-v1`。評估 AHE 是否清楚表達當時可查證的系統狀態，讓人類或其他代理能核對決定及結果。**可追溯是基本要求；減少沒有新增依據的錯誤重試，是進一步收益。** 解題輪數與測試成功率仍保留，但不替代這兩項目標。

本方法補充 [拒答與收手方法](DECISION_RESTRAINT_EVALUATION.md)，不改寫其 `decision-restraint-v1` 定義。新實驗須先固定本方法的版本、範圍與判準。套用既有資料時標為事後分析，保留原成績、原契約，以及無法回補的資訊。

## 三層狀態要分清楚

| 層次 | 要還原的內容 | 不能因此聲稱 |
| --- | --- | --- |
| 被研究系統 | 程式／設定版本、候選補丁、測試環境、操作前後狀態、觀測時間 | 選定測試全過等於整個系統正確；每輪重回原版等於程式持續演進 |
| AHE 證據庫 | 當時範圍內的來源與版本、接納狀態、已知有效／失效支持、衝突、缺件、覆蓋限制 | 入庫等於語意正確；未查到等於不存在；沒有測到衝突就代表沒有衝突 |
| 模型可見資訊與決定 | 本次請求、已送達正文／片段、工具錯誤、最終主張與引用、候選和實際動作 | 庫裡有等於模型收到；收到等於採用；輸出的 thinking 等於內部因果解釋 |

每個結論都要綁定時間、版本及查詢範圍。撤回或更新之後，仍能區別「當時成立」與「現在成立」。未演練過這類變動，就將能力標為本次未測，不能由靜態紀錄可還原推廣出去。

AHE 保存證據；模型的決定與評測結果可以由外部流程保存，再綁定當時的證據快照與引用。不得把模型解釋自動接納為事實，也不要求 AHE Core 控制模型的查詢或修補策略。

## 每輪交接卡

每輪先提供一份可讀的交接卡，詳細原文作為可追溯附件。最少包含：

| 欄位 | 必須交代什麼 |
| --- | --- |
| 當時範圍 | 題目、版本、必要前提、已知限制；完整性尚未驗證也要寫明 |
| 當時已知 | 來源、有效支持與反證、此前哪份候選在何種條件下得到什麼結果 |
| 尚未釐清 | 真正缺少、可取得但未送達、交付失敗、語意尚未驗證分開 |
| 實際取得 | 模型請求與工具回覆的連結；目錄、正文及截斷片段分開 |
| 本次決定 | 模型原文、行動範圍、精確引用、候選內容與識別；記錄說明者是模型、控制器或事後評估者 |
| 依據核對 | 引用是否匹配、是否真的支持主張、相反證據如何處理；未知不可補成合理 |
| 和前次差異 | 來源／條件／方案／可套用性改變了什麼；若要重試，當時聲明的目的與依據是什麼 |
| 結果與限制 | 有無真正執行、哪些通過／失敗、是否修正先前判斷；尚未知道根因就保持未知 |

評估者的事後解釋要另列，不能回填成模型當時的理由。能說明「候選引入解包錯誤，所以這次測試失敗」，不等於已證明原問題的全部根因；能列出成功測試，也不等於已證明模型提出方案時的每項主張。

## 三個主要觀察面向

| 面向 | 單位與分母 | 記錄方式 |
| --- | --- | --- |
| 狀態是否可還原 | 開跑前指定的全部決策事件 | 逐事件核對版本、證據狀態、模型可見內容、決定及結果是否能串接；列完整、部分、缺失、不適用。另列哪些需靠外部紀錄，哪些由 AHE 直接提供 |
| 決定是否有可核對依據 | 所有已輸出的指定主張／行動決定 | 分開列有精確引用、引用真正支持、遇到反證仍有可成立支持、理由不足、尚不能判定。引用字面匹配只算第一步，不能當作支持成立率 |
| 重試是否增加可說明的資訊 | 原判準下所有重試事件 | 列改了方案、修復交付、改變相關條件、驗證不確定性、未交代新增依據、未知；另記補丁相同與結果相同，不能只靠這兩項判定無理 |

不合成總分。每項公布分子／分母與未知數，保留輸出失敗及交付中斷；不同單位不相加。連續輪次不是獨立樣本。成功後固定輸入重現，是另一項量測，不用它替代決策有據。

「別人能接手」須另外驗證：讓不知道結果的覆核者根據同一份交接卡，指出版本、已知／未知、支持／反證、允許行動及結果範圍，再比較答案。原作者可以串起檔案，尚不等於獨立交接成功。本次沒有進行這項覆核。

## 怎麼判斷重試

重試單位與觀察窗口須先固定。例如，SWE 每輪是針對同一原始版本提交一份完整候選；不同語句描述同一方案不算新的功能修改。

| 情形 | 可接受的重試理由 | 還需要分清楚的事 |
| --- | --- | --- |
| 前次沒有成功交付／執行 | 修正不可套用補丁、修復連線，首次完成有效評測 | 若更早已有同一補丁的有效失敗，修正本次格式不會消除那份反證 |
| 方案或必要前提改變 | 說明改動針對哪個失敗、哪份來源支持它，以及準備驗證什麼 | 新 patch bytes 可能只是換行；有新候選也不代表說明正確 |
| 原環境／測試不可靠 | 有具體故障紀錄，或事先聲明驗證偶發性／重現性的目的與停止規則 | 環境指紋相同不證明測試完全確定；也不能無據假設偶發性 |
| 重回較佳但未完成的候選 | 明確交代比較基準、取捨與下一步 | 若沒有這段交代，只能記錄觀察到退回舊方案 |
| 補丁與已知評測條件相同，先前已失敗 | 檢查是否有上述可核對理由 | 沒有寫理由時標「未交代重試依據」，不聲稱模型內部沒有理由 |

「新增資料」還要區分：入庫、可查、實際送達，以及與先前反證相關。單純增加歷史目錄、識別碼、篇幅或工具次數，不自動構成重試的有效依據。

若要量化「可避免的重複失敗」，未來須同時檢查：同一候選已有有效失敗、相關失敗證據確已送達、相關條件未變，且沒有預先允許的重測目的或新支持。條件缺少就分列，不能把未收到反證的事件算成「明知失敗仍硬做」。也不因新方案最後失敗就倒推它不值得試。

原協定若要求重複候選也完整評測，就照樣保存結果；本方法評估模型候選與說明，不回溯把遵守評測協定當成錯誤，也不授權自動去重、改提示或跳測。

## 後續實驗採用與本次回看

未來先固定系統狀態問題、證據範圍、可接受理由、重試目的、未知分類與交接判準，再蒐集結果。保留任務進展／回歸及過度停手兩項護欄，避免只追求少試幾次而讓任務停擺。

若為了蒐集重試理由而新增模型輸出欄位，須宣告為新契約與新實驗版本；不能假裝和舊提示相同。本次只根據既有 final、引用、實際交付與收據回看，不以新欄位要求改判舊契約違規。
